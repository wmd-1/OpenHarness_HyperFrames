四、实施中修正的真实后端事实（关键）
  1. 真实栈需要签发 API Key（scripts/manage_api_keys.py create），否则建会话返回 401。
  2. 轮次列表端点 GET /v1/sessions/{id}/turns 响应体为 { items: [...] }（非 turns），
     artifact 直链为 /v1/sessions/{id}/turns/{turn_index}/artifact?api_key=&mode=stream。
  3. WS 状态属性 data-ws-status 实际值为 ready（非 connected）。
  4. 登录需点击「保存」按钮；关闭会话需用 /close 命令（历史卡片关闭按钮存在歧义）。
  5. 首页为静态模块卡片，登录后落在首页而非视频模块；触发 401 需进入 /video。
  6. 每租户并发配额 OH_TENANT_MAX_CONCURRENT 默认 1；E2E 栈放宽至 12。
  7. Playwright 容器以 --network host 运行，使用动态空闲端口 E2E_PORT，vite 代理 /v1 → localhost:8001。
  8. 每租户每日建会话配额 tenant_max_daily 默认 200（env OH_TENANT_MAX_DAILY）；
     耗尽后返回 403 daily_quota_exceeded，表现为无关用例批量失败，极易误判为测试 bug。
  9. 软关闭（DELETE）为 read_only：会话仍保留、da.currentSessionId 不清空、前端输入框禁用。
  10. turn_complete ≠ 后端空闲：WS 发出 turn_complete 后 turn_task 仍在收尾，此时立即提交下一轮
      会被后端以 {"type":"busy"} 拒绝 —— 真实竞态窗口（前端 UI 此时已可输入）。
  11. 建会话 503 的全局横幅抑制按请求 pathname 判定，测试用 route.continue({url}) 追加 query 不破坏抑制。

五、本轮 E2E 发现并修复的前端缺陷
  WS busy 帧未回滚乐观 turnActive：submit 时乐观置 turnActive=true，收到 busy 只加一条 warning，
  未回滚 → 输入区永久停留「轮次执行中」，只能刷新页面恢复。
  修复：src/ws/useWebSocket.ts 的 busy 分支增加 conv.setTurnActive(sid, false)。
  回归单测：src/ws/__tests__/useWebSocket.test.ts ▸「busy 帧回滚乐观 turnActive」。
  （该缺陷只在真实后端 + 真实浏览器下暴露，mock 后端不会产生 busy 竞态。）
